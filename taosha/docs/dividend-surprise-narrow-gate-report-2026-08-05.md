# exp19 `dividend_surprise` · 冻结前只读准确性窄闸报告

- 日期：2026-08-05（UTC+8 / Asia/Shanghai）
- 授权令：`taosha/docs/dividend-surprise-narrow-gate-order-2026-08-05.md`
- 二元结论：**可进入 PAP 草案**
- 限定：可进草案不等于可冻结；历史初始预案值、零分母规则与分红事实资产未闭合前不得冻结。

## 一、结论先行

exp19 的统计形态不构成阻塞：增/减事件可沿既有 signed 单事件集路径合并成一个顶层 ADJ-BMP 判决，不需要新统计能力。

数据侧存在一个高风险但可在冻结前闭合的问题：Tushare `dividend` 接口把 `ann_date`定义为“预案公告日”，并提供税前每股分红、实施进度、基准股本与显式请求后返回的 `update_flag`；但形态探针显示，2011–2018 年的历史年度组只保留实施态行，预案阶段行结构性缺席。实施态的每股数可能按公告后的新基准股本调整，不能直接冒充公告当日初始预案值。

因此可以在数据盲状态下起草 PAP，先锁定指标、边界和 fail-closed 规则；但冻结前必须用全量数据与公告原件证明初始预案值的可得范围，不能用后续实施值回填历史。

## 三、官方接口能力

Tushare 官方 `dividend` 文档将字段定义为：

- `end_date`：分红年度；
- `ann_date`：预案公告日；
- `div_proc`：实施进度；
- `cash_div_tax`：每股分红（税前）；
- `cash_div`：每股分红（税后）；
- `imp_ann_date`：实施公告日；
- `base_date/base_share`：基准日与基准股本。

官方文档：<https://tushare.pro/document/2?doc_id=103>。

官方常见问题另说明：财务数据重复通常来自修订，`update_flag=0`为初始数据、`1`为修正后数据；字段不在默认输出时须在 `fields` 中显式点名。来源：<https://tushare.pro/document/1?doc_id=122>。

当前 token 实测可调用 `dividend`。显式请求17个字段后，接口确实返回 `update_flag/base_date/base_share`，三者均可用于版本与基准股本审计。

## 四、30票限量形态探针

探针选择30只证券，刻意混合持续分红公司、年轻上市公司与分红稀疏/风险证券；只用于识别字段和污染形态，不是随机样本，不得外推市场频率。全程逐票读取、零缓存入仓、零落库、零收益字段。

### 4.1 总体结构

| 指标 | 实测 |
|---|---:|
| 请求证券 | 30 |
| 成功返回证券 | 30 / 30 |
| 返回原始行 | 1,443 |
| 年度行（`end_date`为12月31日，全历史） | 1,011 |
| 年度组（`ts_code,end_date`，全历史） | 583 |
| 完全重复行 | 0 / 1,443 |
| 年度行 `update_flag=0 / 1` | 996 / 15 |
| 年度组存在后续修订行 | 7 / 583 |
| 年度组跨阶段每股值冲突 | 15 / 583 |
| 年度组跨阶段公告日冲突 | 28 / 583 |
| 初始税前每股分红为0 | 56 / 583 |
| 必需字段缺失（全历史） | `ann_date 12 / cash_div_tax 6`；其余核心字段0 |

阶段分布为：`实施 537 / 股东大会通过 237 / 预案 236 / 未通过 1`。这说明 `div_proc` 是生命周期阶段，而不是“一组只出现一次的事件类型”。

### 4.2 研究窗内存在明确的历史覆盖断点

以 `2011-01-01 ≤ ann_date < 2024-07-01` 仅作本轮核验窗，30票共有355个年度组：

| 公告年 | 年度组 | 可由 `div_proc=预案` 且初始值唯一识别 |
|---|---:|---:|
| 2011 | 20 | 0 |
| 2012 | 20 | 0 |
| 2013 | 21 | 0 |
| 2014 | 24 | 0 |
| 2015 | 23 | 0 |
| 2016 | 23 | 0 |
| 2017 | 24 | 0 |
| 2018 | 23 | 0 |
| 2019 | 29 | 29 |
| 2020 | 29 | 29 |
| 2021 | 30 | 30 |
| 2022 | 30 | 30 |
| 2023 | 30 | 30 |
| 2024 | 29 | 29 |
| **合计** | **355** | **177** |

2011–2018 的178/178组均无预案阶段行，只剩实施态等后续阶段；2019起才在该探针中完整出现预案阶段。这是结构性时间断点，不是零星缺失。

不能用 `update_flag=0` 把阶段行全部折叠后任取一个值。例：`000002.SZ/20191231` 的预案、股东大会通过、实施三行均为 `update_flag=0` 且 `ann_date=20200318`，税前每股值却依次为 `1.045 / 1.016613 / 1.0166131`，基准股本日期随阶段变化。若取实施行，就用到了事件日后的股本调整结果。

另一例 `000002.SZ/20181231`：初始预案为 `update_flag=0,cash_div_tax=1.07`，其后预案修订及通过/实施行均为 `update_flag=1,cash_div_tax=1.045102`。这证实 `update_flag` 对修订有用，但不能替代 `div_proc` 的阶段识别。

## 五、50%核验值下的样本漏斗（仅探针）

严格采用“年度预案阶段 + `update_flag=0` + 公告日和税前每股值各唯一”的机械读法，177个当期组中：

- 30组没有可按同一严格口径取得的上年组；
- 147组具备相邻年度对；
- 其中27组上年值为0，百分比变化数学无定义；
- 剩余120组可计算同比：`up≥50%` 14、`down≤−50%` 6、区间内100；
- 核验候选合计20/120（增14、减6）；
- 恰等+50%和−50%各1例，冻结时必须明确采用闭区间还是开区间。

| 2021 | 29 | 5 | 3 | 0 | 21 |

这些数字只证明候选机制可计算且零分母真实存在，不是全市场候选估计。全市场正式数量当前无法量化。

## 六、事件定义可确定部分与待人裁定

### 6.1 可确定部分

- 事件锚候选只能取 `ann_date`；`end_date`只标报告年度，`imp_ann_date/record_date/ex_date/pay_date`均不得替代事件日；
- 为避免税制差异，跨年可比值应优先使用官方定义为税前每股分红的 `cash_div_tax`；`cash_div`不能与其混用；
- 年度限定应显式要求报告期为12月31日；半年度、季度或特殊中期分配不得静默并入年度比较；
- 初始预案与后续修订、通过、实施行必须分开，后续基准股本调整不得回填事件日分类；
- 增/减进入 signed 主事件集；无变化、区间内、不可判只做计数，不得进入方向白名单。

### 6.2 PAP草案阶段须由人裁定

1. **指标范围**：只比较税前现金分红 `cash_div_tax`，还是把送股/转增纳入“每股分红”；后者不是同一单位，不能直接相加。
2. **历史初始值策略**：冻结前补齐原始预案公告值，或明确缩短研究期；不得拿实施态值冒充历史初始预案。研究期选择必须按数据可证明范围留痕，不能按收益结果调整。
3. **零与缺失**：上年显式为0、上年没有任何分红行、上年组存在但不可判，三者必须分开。百分比口径下上年为0应默认不可判；若要把“0→正”定义为增加事件，属于新增离散规则，须人明确裁定。
4. **阈值边界**：登记的50%仍是待冻结值；若采用，应明确 `≥+50% / ≤−50%` 含端点，不能因边界样本数改判。
5. **阶段与版本异常**：初始预案多行、多公告日、多税前值、`update_flag`缺失或未知值、同票同日方向冲突，逐类选择整组fail-closed或其他明确规则，不得任取最早/最晚/最新。

## 七、判决形态与最小缺口

现有统计能力足够：

- `up=+1 / down=−1` 可沿 exp20/exp17 的 `direction_signed_main` 事件级逐τ符号变换；
- 主事件集只产生一个 `adj_bmp_main_only` 顶层 verdict，不按增/减分拆α；
- 增/减 raw 结果只作结构化 NOT_FOR_VERDICT 诊断；
- A股行情、交易日历、全市场等权基准、三窗口、聚集校正与 `llm/prescreen` 水印均已有路径。

冻结前真正缺失的最小件：

1. `dividend` append-only 全量事实批次，字段必须包含 `update_flag/base_date/base_share`；
2. current/snap 最小只读视图与 StudySnapshot 路由；
3. 全量阶段、修订、零分母、缺年与年度覆盖断点量化；
4. 对历史预案值做公告原件/官方索引抽核；若不能证明公告当日初始值，必须停止冻结或由人明确缩短研究期，不得回填实施值。

冻结后才需要 exp19 专属事件生成器、driver、report 与攻击 fixture；本轮未实现。

## 八、二元结论与下一停点

**结论：可进入 PAP 草案。**

理由：登记命题能被结构化地写成年度、初始预案、税前每股值、同比方向与 signed 单判决；官方接口真实可用，现有统计内核足够。当前缺口属于冻结前数据与口径闭合，不是必须先建设新统计能力的 PAP 阻塞。

草案必须标记 NOT-FROZEN，并把以下内容写成冻结硬门：历史初始预案值可证明范围、零/缺失分母规则、全量数据资产和污染计数。未闭合不得冻结。

下一步只能由人另令 exp19 NOT-FROZEN PAP 草案；不得直接采集全量、落库、冻结、运行或persist。exp18继续停在既有首次披露语义硬门，不与exp19并行恢复。

## 九、证据边界与复现说明

- 数据库查询均在 `BEGIN READ ONLY` 会话中执行，实测 `transaction_read_only=on`；
- 官方接口探针只读取30只列名已列证券，全程零数据库写入、零缓存入仓；
- 探针显式请求字段：`ts_code/end_date/ann_date/div_proc/stk_div/stk_bo_rate/stk_co_rate/cash_div/cash_div_tax/record_date/ex_date/pay_date/div_listdate/imp_ann_date/base_date/base_share/update_flag`；
- 分组键=`(ts_code,end_date)`，Decimal用于50%边界比较；
- 未读取任何事件日后收益、CAR或显著性；
- 未生成PAP、冻结、manifest、正式运行或persist；
- 未制作频率图，因为30票为刻意形态样本，图形化占比会制造总体代表性错觉；以审计表呈现更忠实。
