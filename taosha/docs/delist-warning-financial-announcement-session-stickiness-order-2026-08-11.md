## 二、只读诊断

失败日两遍请求参数逐字相同，均返回 32 行且各自无重复；共同 30 行，A/B 各有 2
个独有公告 ID，共同行逐字段相同。第一页 `totalAnnouncement` 在 32 与 35 间漂移，
第二页又返回 32，证明不是规范化、排序或字段比较错误，而是一次分页过程落入不同
官方会话/后台索引视图。

官方响应设置 `JSESSIONID`。固定同一 Cookie 会话后，预先限定的 1→2→1→2 四次
只读探针两遍均得到 `35=30+5`，ID 集一致；故根因是现有客户端没有在同一进程内
保留官方会话 Cookie。

## 三、唯一允许的窄修

1. `qbase.ingest.cninfo` 的 GET/POST 共用一个进程内 Cookie-aware opener，忠实保留
   官方响应的 `JSESSIONID`；重试、限流、超时和响应解析语义不变。
2. 新写入只允许进入 `bisect_v7`；`bisect_v6` 加入旧布局白名单，仅作只读自验。
3. fixture 必须机械证明 GET/POST 共用同一 opener 且 opener 含 CookieProcessor；必须
   证明 v6 失败证据不覆盖、v6 合法 marker 仍可自验。
4. 单日多页仍须 pass A/B 各自完整分页、每遍跨页 ID 唯一、非终页满 30、总行数
   命中各页计数观测、两遍规范化全集逐字段相等才接受。
