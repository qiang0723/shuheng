## 三、forecast 定位器只说明召回面，不能形成事件集

在 current 财务底座上，forecast “商誉”文本定位器给出2,681行 / 2,023组。它只用于选择公告抽核对象，不是全量商誉减值候选：

`2,681 = 归母权益为正 2,589 + 归母权益为负 40 + 分母版本不可判 52`

该三分只是分母形态诊断。它没有证明金额来自商誉专属减值、没有证明首次合格披露，也无法量化标题/文本未含“商誉”的漏检。因此不能据2,023组推断频率、覆盖、候选数或研究期起点。

## 四、官方原件联合硬门仅1/23通过

### 4.1 通过定义

“可证明”必须同时满足：

1. 巨潮官方元数据与发行人 PDF 能定位 F1 四类载体之一；
2. 正文给出本期商誉减值的精确金额，或区间下限可判，币种和单位明确；
3. 商誉金额能与无形资产、其他资产或资产减值总额分离；
4. 能证明同一事项的首次达到阈值可判披露及后续修订关系；
5. 事件前最近一份归母权益版本唯一、为正且报告期可证；
6. 统一单位后以 Decimal 精确执行 `amount / prior_parent_equity >= 0.05`。

任一失败即整组 fail-closed；标题、报告期末、入库时点及后验年报均不构成公告锚。

### 4.3 v1→v2 只修检索窗口，没有放宽证据标准

v1 将公告检索起点放在报告期次年，漏掉可能早于报告期末发布的预告。v2 改为从报告期所在年1月1日检索，并补入显式“修正”文书标记；公告日、金额专属性、单位、区间、修订关系和分母标准均未放宽。v1/v2 原件与结果分目录保留，二者最终均为1/23通过；v2 只消除了检索窗口假阴性，没有救活联合硬门。

v2 首次网络读取在2/23处遇 `IncompleteRead`，已保存 checkpoint 与日志；随后只从 checkpoint 恢复官方原件读取，不改变样本、判据或已有原件。

## 五、正文中“有数字”不等于机器可证明本期商誉减值额

对v2已保存的164件 PDF 做只读、非事件资格的片段诊断：

| 诊断 | 件数 |
|---|---:|
| PDF总数 | 164 |
| 正文含“商誉” | 90 |
| “商誉”附近出现“元/万元/亿元”数字 | 74 |
| 严格解析 qualified | 2 |

这74件混合了商誉余额表、并购形成商誉、诉讼最大损失、资产组合金额、预估金额和真实减值准备。例如正文可能同时给出“确认商誉216,655,732.58元”和“拟计提约2,500万元”，也可能在财报表格中并列期初余额、期末余额与减值准备。只靠邻近数字会把余额或组合金额错当事件分子。

因此正确结论不是“官方原件没有金额”，而是：**现有最小规则无法在大规模原件中可靠分离本期商誉专属减值、事项身份、首次可判披露和修订链。** 继续扩展为通用表格解析、OCR或大规模人工判读，属于施工令第四节要求先停报人的平台扩建，不在本单元内继续。
